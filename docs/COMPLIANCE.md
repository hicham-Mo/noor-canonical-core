Lawful Basis\n- Data processing must be lawful, fair, and transparent\n- Processing must have a specified, explicit, and legitimate purpose\n- Data subjects must be informed about processing\n\n#### 2. Data Minimization\n- Collect only data necessary for the stated purpose\n- Do not collect excessive data\n- Review data regularly to ensure relevance\n\n#### 3. Purpose Limitation\n- Use data only for the stated purpose\n- Do not repurpose without explicit consent\n- Document all purposes clearly\n\n#### 4. Retention Periods\n- Define retention periods based on purpose\n- Delete data when no longer needed\n- Maintain records of deletion\n\n#### 5. Data Subject Rights\n- **Right to Access**: Provide data within 30 days\n- **Right to Rectification**: Correct inaccurate data\n- **Right to Erasure**: Delete data under certain conditions\n- **Right to Restrict Processing**: Limit how data is used\n- **Right to Data Portability**: Receive data in structured format\n- **Right to Object**: Opt-out of processing\n\n#### 6. Data Processor Agreements\n- Establish written contracts with data processors\n- Specify processing instructions\n- Ensure confidentiality and security measures\n- Define liability and indemnification\n\n#### 7. Security Measures\n- Implement appropriate technical and organizational measures\n- Encrypt sensitive data\n- Control access with authentication\n- Monitor for unauthorized access\n- Maintain audit logs\n\n#### 8. Breach Notification\n- Notify CNIL of breaches without undue delay\n- Notify affected individuals within 72 hours\n- Document all breaches and responses\n- Provide remediation details\n\n### Implementation in Noor\n\n```python\n# All data handling includes:\n- Purpose documentation\n- Retention period tracking\n- Access control logs\n- Encryption in transit and at rest\n- Breach notification procedures\n- User consent management\n```\n\n### Compliance Checklist\n\n- [ ] Privacy policy published and accessible\n- [ ] Data processing agreements in place\n- [ ] Retention schedules defined\n- [ ] Access controls implemented\n- [ ] Encryption enabled (transport & storage)\n- [ ] Audit logging active\n- [ ] Breach response procedure documented\n- [ ] User rights procedures implemented\n- [ ] CNIL registration completed (if required)\n- [ ] Data protection impact assessment (DPIA) conducted\n\n---\n\n## Islamic Finance Principles\n\n### Prohibited Activities (Haram)\n\n#### 1. Riba (Interest/Usury)\n- Interest-based loans prohibited\n- Fixed returns on loans forbidden\n- Excess in exchange not allowed\n\n**Implementation**:\n```python\ndef validate_no_riba(transaction):\n    if transaction.includes_interest:\n        raise IslamicComplianceError(\"Riba prohibited\")\n    return True\n```\n\n#### 2. Gharar (Excessive Uncertainty)\n- Contracts must be clear and certain\n- Hidden terms forbidden\n- Ambiguous agreements invalid\n\n**Implementation**:\n```python\ndef validate_contract_clarity(contract):\n    required_fields = ['parties', 'goods', 'price', 'terms']\n    for field in required_fields:\n        if not contract.get(field):\n            raise IslamicComplianceError(f\"Gharar: {field} not specified\")\n    return True\n```\n\n#### 3.
